# 企业分布热力图

默认只查询存续企业，产业使用 Techin「所属产业」分类。第一版覆盖深圳；其他地区先说明未验收。企业清单不必单独输出。

## 首次使用：连接使用者自己的 Techin

不依赖GPT模型或OpenAI API，不使用Codex专用工具。先检查当前使用者的 Techin MCP 连接。未配置或认证失败时，暂停取数，指导使用者在所用平台的 MCP/连接设置中，使用 Techin 官方提供的服务地址，将自己的 API Key 填入 `X-Techin-Api-Key` 请求头。不要让使用者把 Key 发到聊天里。不得内置开发者 Key、共享开发者连接配置、复制本机凭证或借用其他用户账号。当前连接可用时无需重复输入；更换账号通过平台连接设置完成。连接后用 list_datasets 验证访问权限，失败时不回显凭证。

技能包不含 Key、个人配置、真实企业查询数据或查询日志。凭证只由使用者所在平台保存，不写入技能、HTML、JSON、日志或示例。安装技能不会自动安装或配置 Techin 服务。

## 执行

1. 检查 Techin MCP 是否可用；读取企业全景画像字段。调用 match_industry 匹配产业，按工具要求确认匹配口径，保留返回的 paths。地区筛选带完整已指定层级：区级查省、市、区；街道级加街道，不默认某个街道，避免同名地区。
2. query_stat 使用预定义「企业数量」获取同条件数量；query_detail 读取企业名称、统一社会信用代码、注册地址、高德经纬度。每页不超过100，按信用代码稳定排序，逐页取齐。单页失败最多重试2次，返回文本含错误也视为失败。记录所有服务端 adjustments。不能用部分结果冒充完整取数。
3. 明细以信用代码去重，总数必须与同次统计一致。保存 JSON：meta 包含 title、expected_total、coord_system（GCJ-02）、region、产业、存续状态、查询日期、查询条件与调整；enterprises 含 name、credit_code、address、lng、lat。
4. 按[自动边界流程](references/boundaries.md)执行：使用者已明确非商业学习研究时，调用scripts/fetch_boundary.py自动取得目标范围，不要求手动找文件；用途未知先确认。默认研究出图采用--preview，不加--boundary-verified。遇网站限制停止，不绕过。另有合法且独立核验的边界才进入正式模式。高德字段按GCJ-02转WGS84，百度字段不能混用。
5. 运行 scripts/render.py。只剔除可靠边界之外且距边界超过100米的明显位置错误；距离阈值是初版可配置容差，不代表定位精度。最多5家且不超过完整企业数1%，超过则停止。边界附近保留。不得因远离企业群而删除企业。缺坐标保留原始记录，不上图。
6. 交付 HTML、原始 JSON 和 audit.json，保存到使用者指定的本地输出目录，避免将数据写入安装技能或Git仓库中。地图不显示剔除说明，审计保留原因。图上企业注册地址来源标明为Techin，不冒充底图楼宇标签。

## 命令

`python3 scripts/render.py --data 企业数据.json --boundary 边界.geojson --boundary-crs WGS84 --boundary-verified --out 地图.html`

非商业研究边界尚未独立验收时使用 `--preview`，此时核验状态仅保留在审计文件，地图不显示开发备注，不能报告为正式验收结果。公开包不附带候选边界。Agent优先按references/boundaries.md自动获取非商业研究边界；禁止从开发者机器或聊天历史复制边界、凭证、企业数据。缺边界时先明确缺少的输入，再暂停正式出图。

地图将目标行政范围保留清晰，范围外覆盖灰色遮罩，蓝线标出边界。范围外点位不显示，原始企业记录仍完整保留；显示筛选不等于剔除数据。

默认底图OpenFreeMap，免地图Key但需联网；依赖MapLibre。地图背景可以包含道路及建筑轮廓，楼宇/园区名称覆盖尚不完整。坐标转换无法修复错误注册地址或粗略定位，不宣称楼宇精度。

显示样式：外围使用浅灰半透明遮罩（0.48）；集聚气泡按当前地图缩放合并相近企业，并继续合并可能重叠的气泡。气泡大小随企业数量增加，数字为实际数量，颜色档位为1–4、5–19、20–49、50及以上；这不是单位面积密度。点击气泡查看企业，放大重新分组。

## 16:9信息图

用户需要PPT尺寸图片时，另生成1920×1080 PNG，左侧信息卡与紧凑代表企业列表、右侧贴合行政区形状的完整范围热力图，减少周边空白。沿用完整取数和边界核验流程。

在相同地区、产业、存续条件下，query_stat读取预定义「企业数量」「高新企业数量」「专精特新企业数量」「专精特新小巨人企业数量」「上市企业数量」。分别展示，可能重叠，不相加，不把专精特新企业数量直接解释为包含小巨人的去重合计。每次先核对字段可用性。

展示企业使用「有效科技认定」；先读取get_field_enums，再用精确合法标签contains_any查询。禁止模糊词like猜标签；代表企业参考Techin「企业综合评分-总分」降序、信用代码升序的前10家，再补入未入选的最高分小巨人、独角兽各1家，最多12家，保留评分与原始标签证据。评分或标签缺失则减少展示，不凭知名度猜选，不宣称预测潜力。代表企业需属于完整企业结果。上市标签来自「是否上市公司」，不能由名称或集团情况推断。显示短标签：国高企业、专精特新、专精特新小巨人、上市企业、独角兽；独角兽不得混入潜在/未来独角兽。成图只展示名称与短标签，选择规则与重叠口径仅留审计。没有可靠标签则不放企业选例；不补造数字或园区分析。

保存本地summary.json：total、hightech、specialized、little_giant、listed_total（整数）、region、industry、status、fetched_at，与完整数据一致；representatives含name、credit_code、tags（展示标签数组）、raw_tags（Techin原始标签），记录metric_fields、filters、adjustments、selection。

运行 `python3 scripts/render_report.py --data 企业数据.json --boundary 边界.geojson --boundary-crs WGS84 --boundary-verified --summary summary.json --out 信息图.html`。自动获取的非商业研究边界使用--preview，正常生成图片，不能改称精度已核验。打开导出页，联网等待底图完成，点击「导出PNG」。自动化环境可将页面生成的result图片保存为PNG；检查图片确为1920×1080、地图完整、文字无溢出且统计与查询一致后交付PNG。HTML导出页也交付，浏览器不支持下载时可以右键生成图片保存。

保留地图版权署名。成图不出现开发备注，真实核验状态仍记录在audit.json。统计总数指Techin行政字段查询结果；只在边界内绘制定位点，二者不必一致，审计保留差异。

## 跨平台执行

所有命令中的脚本相对路径从此SKILL.md所在文件夹解析，不能假定当前工作目录。使用当前平台的MCP工具发现能力，按服务暴露的工具名称调用，不依赖固定mcp__前缀。脚本不调用模型API、不读取Techin Key；仅处理Agent通过MCP取得的本地JSON。Windows可用py -3代替python3。输入输出说明见[数据规范](references/data-format.md)。
